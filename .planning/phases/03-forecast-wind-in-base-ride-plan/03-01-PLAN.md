<feature>
  <name>fetch_stop_wind() — per-stop wind data pipeline</name>
  <files>services/weather.py, tests/test_weather.py</files>
  <behavior>
    fetch_stop_wind(stops, track_points, plan_slug, start_time_str, cache=None) -> list | None

    Signature:
    - stops: list of dicts with 'distance_miles' key (and optionally 'arrival_time_min')
    - track_points: list of RWGPS dicts with y, x, d fields
    - plan_slug: str used for cache key prefix "wind:{plan_slug}:{start_hour}"
    - start_time_str: "HH:MM" string for estimated ride start
    - cache: Flask-Caching object or None

    Behaviors to test (TestFetchStopWind class in tests/test_weather.py):

    - test_returns_wind_data_for_each_stop: Given 3 stops and matching track_points with mocked weather API returning valid hourly data, returns a list of 3 dicts each with keys: wind_speed_kmh (float), wind_type (str), style (dict), label (str).

    - test_result_length_matches_stops: Output list length always equals input stops length, even when some coordinates resolve to None.

    - test_cache_hit: On second call with same plan_slug and start_time_str, returns cached result. Verify fetch_route_weather is called only once (mock call_count == 1).

    - test_empty_track_returns_none: When track_points is [] or None, returns None (not an empty list, not an error).

    - test_api_error_returns_none: When fetch_route_weather raises requests.RequestException, returns None.

    - test_none_coordinate_produces_none_entry: When a stop's coordinate can't be resolved (get_stop_coordinates returns None for that stop), the corresponding result entry is None but other entries are valid.

    - test_bearing_uses_consecutive_stops: For a middle stop, bearing is computed from that stop to the next stop (not from previous stop). For the final stop, bearing is from the previous stop to the final stop. Verify calculate_bearing is called with correct lat/lng pairs.

    - test_uses_arrival_time_for_hour_index: When stops have arrival_time_min, the function computes an arrival datetime from start_time_str + arrival offset and uses get_hour_index to pick the correct forecast hour (not always hour 0).

    Implementation notes:
    - Cache key format: "wind:{plan_slug}:{YYYYMMDD}{HH}" where date is today and HH from start_time_str
    - Use get_hour_index(hourly['time'], arrival_dt) per stop to pick the correct forecast hour
    - Use _safe_get() for all hourly data access
    - Wrap fetch_route_weather call in try/except returning None on failure
    - Pass only valid (non-None) coordinates to fetch_route_weather, then map results back to original stop indices
  </behavior>
  <implementation>
    Add fetch_stop_wind() to services/weather.py after get_cached_route_weather().

    Algorithm:
    1. Early return None if not track_points
    2. coords = get_stop_coordinates(stops, track_points) — always len(stops) entries
    3. Build valid_coords list and index mapping (valid_idx -> original_idx)
    4. Early return None if no valid coords
    5. Check cache: key = f"wind:{plan_slug}:{date_str}{hour_str}"
    6. Call fetch_route_weather(valid_coords) in try/except
    7. For each stop: if coord is None -> result.append(None); else use weather_data[valid_index]
    8. Per stop: compute arrival_dt from start_time + arrival_time_min offset, get_hour_index for correct forecast hour
    9. compute bearing to next stop (or from previous for last), headwind_component, crosswind_component, classify_wind, wind_cell_style, wind_label
    10. Build result dict, append to list
    11. Cache result, return

    Reference the pseudocode in 03-RESEARCH.md Pattern 1 but improve it with arrival-time-aware hour indexing per the research recommendation.

    Import datetime at top of weather.py if not already imported.
  </implementation>
</feature>
