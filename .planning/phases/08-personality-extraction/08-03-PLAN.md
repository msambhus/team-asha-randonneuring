  <name>Task 1: Create extract_personality_blog.py — WordPress URL and PDF extraction</name>
  <files>scripts/extract_personality_blog.py</files>
  <action>
Create `scripts/extract_personality_blog.py` as a standalone CLI script.

**CLI arguments:**
- `--url` (optional): WordPress blog URL to extract from (uses trafilatura)
- `--pdf-path` (optional): Local path to a PDF file (uses pdfplumber)
- `--rider-name` (required): Name to look up in rider table (same ILIKE pattern as seed script)
- `--profile-type` (default: 'coach'): 'coach' or 'rider'
- `--dry-run` (flag): Output extracted JSON to stdout, do not write to DB
- Validation: exactly one of --url or --pdf-path must be provided

**Text extraction functions (defined in this file, not in helpers):**

1. `fetch_blog_text(url: str) -> str`:
   - Use `trafilatura.fetch_url(url)` to download HTML
   - Use `trafilatura.extract(downloaded, include_comments=False, include_tables=False)` to get article text
   - Raise ValueError on fetch failure or empty extraction

2. `extract_pdf_text(pdf_path: str) -> str`:
   - Use `pdfplumber.open(pdf_path)` to open PDF
   - Iterate pages, call `page.extract_text()` per page
   - Join non-empty pages with double newline
   - Raise ValueError if no text extracted (may be scanned PDF)

**Script flow:**
1. Parse args, validate exactly one source provided
2. Extract text using appropriate function
3. Compute word count from extracted text for confidence calculation (use word count as proxy for "message count" — `len(text.split()) // 50` to estimate ~50 words per message equivalent)
4. Create OpenAI client
5. Call `client.chat.completions.parse()` directly (not via extract_from_messages since blog text is a single document, not message list). Use a modified system prompt that says "Analyze this blog post by {rider_name}" instead of "Analyze {sender_name}'s messages". Use the same PersonalityExtraction response_format and temperature=0.
6. If `--dry-run`: print extraction as formatted JSON
7. If not dry-run: connect to DB, lookup_rider, store_extraction_results with extraction_source='blog', store_evidence, commit

**Handle Google Drive PDF warning:** If `--url` starts with `https://drive.google.com`, print a warning: "Google Drive URLs may require authentication. If extraction fails, download the PDF manually and use --pdf-path instead." Then attempt the fetch anyway.

**Error handling:** Same pattern as extract_personality_whatsapp.py — missing API key, missing DB URL, extraction failures all print clear messages and exit 1.

<task type="auto">
  <name>Task 2: Create merge_personality.py — combine multi-source profiles</name>
  <files>scripts/merge_personality.py</files>
  <action>
Create `scripts/merge_personality.py` as a standalone CLI script.

**CLI arguments:**
- `--rider-name` (required): Name to look up in rider table
- `--profile-type` (default: 'coach'): 'coach' or 'rider'
- `--dry-run` (flag): Output merged JSON to stdout, do not write to DB

**Core function — merge_profiles(whatsapp_row: dict, blog_row: dict) -> dict:**
Define this in `scripts/personality_helpers.py` (add to the existing file from Plan 02) so tests can import it. Import it here.

Merge rules (from 08-RESEARCH.md):
1. For Literal enum fields (tone, humor_type, directness, encouragement_style, technical_depth, response_length_tendency, question_asking_behavior, domain_bias): use blog value if present, otherwise WhatsApp value
2. For signature_phrases: union of both lists, deduplicated, capped at 5 items (blog phrases first for priority)
3. For topic_biases, topics_allowed: union of both, deduplicated
4. extraction_confidence: use the LOWER of the two source confidence values (conservative)
5. source_message_count: sum of both sources

**Script flow:**
1. Parse args
2. Connect to DB, lookup rider
3. Query personality_profile for rows where `rider_id = X AND profile_type = Y AND extraction_source IN ('whatsapp', 'blog') AND deleted_at IS NULL`
4. If only one source exists, print warning: "Only {source} profile found for {name}. Merge requires both WhatsApp and blog profiles. Run extraction scripts first." Exit 0 (not error).
5. Call `merge_profiles(whatsapp_row, blog_row)` to produce merged dict
6. If `--dry-run`: print merged dict as JSON
7. If not dry-run:
   - Upsert personality_profile with extraction_source='merged' (uses the 3-column UNIQUE constraint)
   - Merge evidence: copy evidence rows from both sources, re-tagged as extraction_source='merged' (DELETE old merged evidence first, then INSERT copies)
   - Commit, print summary

**Evidence merge:** The merged profile's evidence should include quotes from BOTH sources. DELETE from personality_trait_evidence WHERE rider_id=X AND extraction_source='merged', then INSERT copies of whatsapp+blog evidence rows with extraction_source='merged'.

**Print summary:**
```
Merged personality for {rider_name}:
  Sources: whatsapp ({wa_count} messages) + blog ({blog_count} words)
  Merged confidence: {level}
  Tone: {blog_tone} (from blog, whatsapp had {wa_tone})
  ...
  Evidence quotes: {N} total ({wa_evidence} from WhatsApp, {blog_evidence} from blog)
```
