<objective>
TDD: Archive API fetch with 5-day ERA5 fallback and per-stop historical wind orchestration with DB-check-before-fetch persistence.

Purpose: Completed rides need actual wind data from the archive API, but rides within the 5-day ERA5 lag window must fall back to the forecast API's past_days parameter. The orchestration function checks the DB first (STOR-02) to avoid redundant API calls and persists results after a successful fetch.

Output: Two new functions in weather.py, comprehensive tests covering archive/fallback routing, per-stop wind computation, and DB-check-before-fetch/save-after-fetch composition.
</objective>
