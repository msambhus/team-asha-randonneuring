Add `assemble_rider_context(user_id, rider_id)` to `services/chat_service.py`. Follow the research pattern in 02-RESEARCH.md "Pattern 4: Strava Context Assembly" exactly. Key implementation:

1. **Early return on None rider_id** — return `''` immediately. Do NOT query DB with None (Pitfall 3).

2. **Privacy check (SEC-11)**: Look up rider profile. If `strava_data_private` is True, return `''`. Use existing `models.get_rider_by_rusa()` after getting rusa_id, OR add a simpler helper: query `SELECT strava_data_private FROM rider_profile WHERE rider_id = %s`. The research shows a complex path through `_execute` — simplify by adding a `models.get_rider_privacy_flag(rider_id)` helper that returns bool, or inline the query.

3. **Strava check**: Call `models.get_strava_connection(rider_id)`. If None, try brevet history fallback via `_build_brevet_history_summary()`. If that's also empty, return `''` (PERS-02).

4. **Full context build (PERS-01)**:
   - `activities = models.get_strava_activities(rider_id, days=28)`
   - `fitness_score = calculate_fitness_score(activities) if activities else None`
   - `training_summary = _build_training_summary(activities, fitness_score)`
   - `upcoming = models.get_rider_upcoming_signups(rider_id)` — cap at 3 entries
   - Format upcoming as "UPCOMING BREVETS:" section with date, name, distance, status

5. **Return format**: Wrap in `<rider_data>...</rider_data>` XML delimiters (SEC-05 defense).

6. **Also add `assemble_team_context()`** (PERS-03): Non-user-scoped. Calls existing model functions for upcoming rides for the current season and formats as `<team_context>...</team_context>`. This runs regardless of user's Strava status. Use `models.get_current_season()` and `models.get_upcoming_rides_for_season(season_id)` if they exist, otherwise use a simple query for rides with date >= today. Cap at 5 upcoming rides.

7. **Write tests** in `tests/test_chat_service.py`. Use `unittest.mock.patch` to mock `models.*` and `services.*` functions. Test each behavior listed above. Name tests to match VALIDATION.md expectations:
   - `test_context_privacy_flag`
   - `test_context_strava_connected`
   - `test_context_no_strava`
   - `test_context_team_data`
   - `test_context_includes_upcoming_brevets`

Do NOT put rider data in a `role: user` message (prompt injection risk). All context goes in system prompt via XML-delimited blocks.
