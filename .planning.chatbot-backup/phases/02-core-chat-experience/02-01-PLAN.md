  <action>
Create `templates/chat_widget.html` as a self-contained Jinja partial with all HTML and inline JS. Follow the research's widget structure exactly (02-RESEARCH.md "Widget HTML Structure" and "Complete Widget JavaScript" sections). Key implementation details:

1. **Toggle button**: Fixed position bottom-right (24px), z-index 490, uses `var(--primary)` background, speech bubble icon (&#128172;), 52px circle.

2. **Chat panel**: Fixed position, bottom 88px right 24px, z-index 500, 380px wide, max-height 520px, `var(--card-bg)` background, 16px border-radius, flex-direction column.

3. **Header**: `var(--primary)` background, shows "Coach Asha", has History/New/Close buttons. History and New buttons use `rgba(255,255,255,0.15)` background.

4. **Messages area**: flex:1 with overflow-y auto, 12px padding, flex-direction column, gap 8px, min-height 200px.

5. **Input area**: textarea (rows=1, placeholder "Ask about your training...") + Send button. Enter sends (Shift+Enter for newline).

6. **Conversation list panel**: Absolutely positioned overlay inside chat-panel with z-index 510, hidden by default. Back button + "Conversations" title + scrollable list div.

7. **Inline JS** (wrapped in IIFE with 'use strict'):
   - `sessionStorage` read on DOMContentLoaded: if `chatOpen === '1'`, call `openWidget()` (CHAT-02)
   - `toggleChatWidget()`, `openWidget()`, `closeWidget()` — toggle display flex/none, set/remove sessionStorage
   - `handleChatKey(e)` — Enter without Shift calls `sendMessage()`
   - `sendMessage()` — guards `isStreaming`, reads input, appends user bubble, creates empty assistant bubble, uses `fetch('/api/chat/stream', {method: 'POST', ...})` with `ReadableStream` reader. Parses SSE lines from buffer (handles chunk boundaries per Pitfall 2). Extracts `conversation_id` from first event. Appends string tokens to assistant bubble. On `data.error`, shows error text in bubble. On fetch error, shows "Connection error. Please try again." (CHAT-05)
   - `newConversation()` — clears `currentConversationId`, clears messages, appends system note (CHAT-07 prep)
   - `showConversationList()`, `hideConversationList()`, `loadConversation(convId)` — conversation list panel functions (CHAT-06 prep, full wiring in Plan 03)
   - `appendMessage(role, text)`, `appendSystemNote(text)`, `scrollMessages()`, `escHtml(str)` — helpers

8. **base.html modification**: Add `{% if user_logged_in %}{% include 'chat_widget.html' %}{% endif %}` just before the `{% block extra_js %}{% endblock %}` line (around line 161).

9. **Multi-turn**: The widget stores `currentConversationId` from the SSE response's `conversation_id` event. Subsequent messages send this ID, ensuring the server loads history via `get_recent_messages(conversation_id, limit=16)` which provides the last 8 turns (CHAT-03). The limit of 16 (not 20) should be passed from `process_message()` — but that change belongs to Plan 02 where `process_message()` is modified.

Do NOT use EventSource (GET-only). Do NOT create an external JS file. Do NOT add any npm dependencies.
